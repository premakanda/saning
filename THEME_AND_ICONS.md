# THEME_AND_ICONS.md — тема и SVG-иконки для Codex

> Прочитай вместе с `AGENTS.md` и `SITE_CONTENT_BLUEPRINT.md`. Этот документ уточняет оформление, но не переопределяет архитектуру и SEO. Проект: React + TypeScript + Vite + CSS Modules, mobile-first.

## 1. Режимы оформления

- Реализуй светлую и тёмную темы сайта, включая header, footer, меню, карточки, формы, модальное окно, состояния фокуса, иконки и страницы статей.
- **Первый визит:** следуй `prefers-color-scheme` системы. **Явный выбор:** запоминай в `localStorage` под ключом `site-theme` (`light` или `dark`) и используй при следующих посещениях. Не записывай значение, пока пользователь не выбрал тему.
- На `<html>` устанавливай `data-theme="light"` / `data-theme="dark"`. Тема должна применяться **до загрузки CSS/основного React**, чтобы избежать белой вспышки (FOUC). В статически пререндеренных HTML добавь один небольшой безопасный inline-bootstrap в `<head>`, читающий localStorage с `try/catch` и fallback на `matchMedia`. Если среда не предоставляет эти API, используй светлую тему. Для посетителей без JS светлая тема остаётся читаемой.
- Устанавливай `<meta name="color-scheme" content="light dark">`; синхронизируй `color-scheme` в CSS и `theme-color` для браузера там, где это уместно.
- Используй CSS-переменные для семантических токенов: `--color-bg`, `--color-surface`, `--color-text`, `--color-muted`, `--color-border`, `--color-primary`, `--color-primary-contrast`, `--color-focus`. Не копируй всю палитру в каждый CSS Module.
- Проверяй WCAG 2.2 AA: обычный текст не хуже 4.5:1; крупный текст 3:1; графические/интерактивные индикаторы 3:1 там, где требуется. Проверяй контраст в **обеих** темах.
- Переключатель — компактная кнопка в хедере, доступная и на мобильных экранах, с иконкой солнца/луны. Это **button**, не ссылка. Динамический `aria-label`: «Включить тёмную тему» / «Включить светлую тему». Предусмотри видимый фокус и размер касания около 44×44px.
- Не анимируй начальную отрисовку и большие поверхности. При переключении допускается короткая ненавязчивая анимация при отсутствии `prefers-reduced-motion`.
- Смена темы не должна менять разметку, смысл, SEO-метаданные или статические страницы. Сайт должен оставаться индексируемым с выключенным JS.

## 2. Готовые SVG

Директория: `src/assets/icons/`. В архиве — **20 отдельных SVG-файлов**, 24×24 viewBox, единый линейный стиль, `stroke="currentColor"`, без захардкоженных цветов и внешних зависимостей.

| Иконка               | Использование                                   |
| -------------------- | ----------------------------------------------- |
| `wrench.svg`         | общие сантехнические работы, этапы выполнения   |
| `faucet.svg`         | замена смесителя, краны                         |
| `toilet.svg`         | установка унитаза                               |
| `radiator.svg`       | радиаторы отопления                             |
| `floor-heating.svg`  | водяной тёплый пол                              |
| `pipes.svg`          | водоснабжение, разводка труб                    |
| `drain.svg`          | канализация, слив, засоры                       |
| `boiler.svg`         | котельная, котёл (только подтверждённые услуги) |
| `shower.svg`         | душевая, кабины                                 |
| `sink.svg`           | раковина, мойка                                 |
| `leak.svg`           | протечки, капли, ремонт                         |
| `valve.svg`          | трубы, вентили, запорная арматура               |
| `heating.svg`        | общее отопление                                 |
| `phone.svg`          | контакт, телефон                                |
| `sun.svg`            | переход к светлой теме                          |
| `moon.svg`           | переход к тёмной теме                           |
| `check.svg`          | подтверждённые преимущества, этапы              |
| `arrow-up-right.svg` | ссылки/переходы                                 |
| `menu.svg`           | мобильное меню                                  |
| `close.svg`          | закрытие модального окна/меню                   |

Правила:

- SVG иконки — **декоративные** рядом с видимым текстом: `<img src={...} alt="" aria-hidden="true" />`; доступное название предоставляет текст карточки/кнопки. Для переключателя темы доступное название — `aria-label` кнопки.
- Файлы намеренно содержат `currentColor`. Если SVG подключён через обычный `<img>`, цвет **не наследуется** от родителя в большинстве браузеров. Чтобы применять `currentColor`, используй проверенную загрузку SVG **inline как React-компонента** (например, минимально настроенный SVGR), либо CSS `mask-image` с `background-color: currentColor`. Выбери один простой подход и придерживайся его. Не перекрашивай файлы вручную под каждую тему.
- Подключение SVG как React-компонентов требует корректной конфигурации Vite/TypeScript; не делай неработающих импортов `?react` без настроенного плагина.
- Если используешь inline SVG-компонент, задавай `aria-hidden="true"`/`focusable="false"` для декоративных иконок. Смысл передаётся заголовком, текстом или `aria-label`.
- Размеры: 20–24px в UI, 32–40px внутри карточек услуг; не раздувай иконки до уровня фото.
- Не используй эмодзи вместо иконок. Не помещай иконку во все абзацы ради украшения.

## 3. Где нужны иконки, а где фото

**Иконки:** карточки услуг на главной и `/uslugi/`, списки этапов, фактические преимущества, кнопка смены темы, понятные действия интерфейса. Сервисные карточки: один SVG + H3 + короткий текст + ссылка на подтверждённую услугу.

**Фотографии:** hero, реальные выполненные работы, кейсы, обложки статей (только если помогают содержанию), реальные детали монтажа. Для карточек отдельных работ фотография лучше условной иконки; для обобщённых карточек услуг иконка лучше случайного стока.

Фото позже: `src/assets/images/` или `public/images/` согласно принятой стратегии сборки. Не скачивай без разрешения изображения с сайтов конкурентов; не выдавай стоковое фото за реальный объект, бригаду или кейс. Для прототипа используй нейтральный блок-плейсхолдер без публикации как «реальная работа».

Изображения: AVIF/WebP при возможности, корректный `alt`, ширина/высота, `srcset`/`sizes` для отзывчивой сетки, обязательная оптимизация LCP-фотографии в hero, `loading="lazy"` только для находящихся ниже первого экрана. Не размещай существенный SEO-текст внутри картинки.

## 4. Техническая инструкция Codex

1. Скопируй иконки без изменений в `src/assets/icons/`.
2. Настрой глобальные семантические токены двух тем; CSS Modules читают переменные.
3. Добавь небольшой `ThemeToggle` и централизованное управление темой без лишней библиотеки состояния.
4. Выбранный режим хранится локально; первый визит использует системную тему.
5. Важно: внедри раннее определение темы **во все** выходные HTML-файлы SSG, а не только в один SPA `index.html`.
6. Проверь хедер, мобильное меню, hero, карточки, форму, попап, футер и статьи в двух темах на ширинах 320/375/390/768/1024/1440px.
7. Иконки для неподтверждённых услуг можно хранить в проекте, но **нельзя автоматически публиковать** эти услуги и добавлять их в sitemap.
8. Не реализуй доставку заявок сейчас. Остаются только интерфейс и валидация; не создавай иллюзию, что заявка была отправлена.
9. В отчёте перечисли добавленные компоненты, внедрённые темы и реально выполненные проверки.

## 5. Пример токенов (только стартовая палитра, не окончательный дизайн)

```css
:root,
:root[data-theme='light'] {
  color-scheme: light;
  --color-bg: #f7fafc;
  --color-surface: #ffffff;
  --color-text: #17212d;
  --color-muted: #4a5969;
  --color-border: #d5e0e8;
  --color-primary: #115aa3;
  --color-primary-contrast: #ffffff;
  --color-focus: #d97706;
}

:root[data-theme='dark'] {
  color-scheme: dark;
  --color-bg: #111820;
  --color-surface: #1b2632;
  --color-text: #f1f6fa;
  --color-muted: #bac8d4;
  --color-border: #354759;
  --color-primary: #73baff;
  --color-primary-contrast: #0d2338;
  --color-focus: #fbbf24;
}
```

> Когда согласуем фирменный стиль и фотографии, палитру можно спокойно скорректировать. Не придумывай логотип, фирменный шрифт или визуальные доказательства квалификации.
